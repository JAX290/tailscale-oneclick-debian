# 05 · 回滚与救援

## 先记住三件事

1. **云厂商 Web Console / VNC 是你的最后通道**。任何"把自己关在门外"的操作之前，先确认它能登录。
2. **所有修改都有备份**：
   - sshd drop-in 备份在 `/etc/tailscale-oneclick/sshd-dropin.bak`
   - 原 `sshd_config.d` 文件不会被删改（只加了一个 `99-*.conf`）
3. **脚本都是幂等的**：重跑不会重复破坏，只会补齐缺失步骤。

## 场景一：收口后连不上服务器

从云厂商 Web Console（或 VNC）进去，root 执行：

```bash
# 1) 先看 sshd 是否还活着
sshd -t
systemctl status ssh --no-pager

# 2) 撤销收口（恢复 0.0.0.0:22 监听 + 原来的 sshd 设置）
bash install.sh --unlock

# 如脚本不在本机，直接手动删掉 drop-in：
rm -f /etc/ssh/sshd_config.d/99-tailscale-oneclick.conf
systemctl reload ssh

# 3) 确认公网 22 回来了
ss -ltn | grep :22
```

## 场景二：Tailscale 自己坏了

```bash
systemctl status tailscaled --no-pager
journalctl -u tailscaled -n 100 --no-pager
tailscale up          # 重新登录（可能需要重新授权）
```

如果 tailscaled 起不来（升级坏了、路由冲突），也可以：

```bash
apt-get install --reinstall -y tailscale
systemctl restart tailscaled
```

**不要**在 `--lockdown` 状态下卸载 tailscale —— 那会同时失去唯一入口。先 `--unlock`。

## 场景三：sudo 被搞坏（理论上不该发生）

安装时 sudoers 是"校验通过才原子替换"，但如果你手动改过：

```bash
# 从 console 以 root 登录（不依赖 sudo）
visudo -c
# 有问题就删掉/修复
rm -f /etc/sudoers.d/90-opsagent
visudo -c
```

## 场景四：ACL 改崩了

控制台 Access Controls 页面 → 右上角历史版本 → **Revert**。
或者把改前的 JSON 粘回去。本仓库不自动改 ACL，所以这一步永远是人操作。

## 场景五：完整卸载

```bash
# 保留 tailscale 和 tailnet 登录，只删本脚本加的东西
sudo bash uninstall.sh

# 连 tailscale 一起删（会退出 tailnet）
sudo bash uninstall.sh --purge-tailscale

# 保留 opsagent 账号（比如还想用它的日志权限）
sudo bash uninstall.sh --keep-user

# 先看会做什么
sudo bash uninstall.sh --dry-run
```

卸载顺序（脚本内部已按此顺序）：

1. 撤销 sshd 收口并 reload（优先恢复访问）
2. 删 `/etc/sudoers.d/90-opsagent`
3. 删 `/usr/local/sbin/ops-*` 和 `/etc/opsagent/`
4. 删 audit 规则并 `augenrules --load`
5. 删除 `opsagent` 账号（家目录保留）
6. 可选：`tailscale logout` + `apt purge tailscale`
7. 删 `/etc/tailscale-oneclick/`

## 场景六：怀疑被入侵

保留证据优先，不要急着重装：

```bash
# 谁登录过
last -a | head -n 30
journalctl -u ssh -n 200 --no-pager
journalctl -u tailscaled -n 200 --no-pager

# AI/opsagent 执行过什么
sudo cat /var/log/sudo-io/00/00/*/log 2>/dev/null | head -n 200
ausearch -k opsagent-exec -i | tail -n 100

# tailnet 侧：控制台 Machines 看设备列表、Access controls 看规则变更历史
```

处置：

```bash
# 立刻断开这台机器的 tailnet 访问（控制台也能做）
tailscale down
# 移除设备（控制台 → Machines → 该设备 → Remove）
```

## 备份与恢复清单

| 内容 | 位置 | 恢复方式 |
|---|---|---|
| sshd drop-in | `/etc/tailscale-oneclick/sshd-dropin.bak` | `--unlock` 自动恢复 |
| 状态信息 | `/etc/tailscale-oneclick/state.env` | 供 verify/uninstall 读取 |
| 安装日志 | `/var/log/tailscale-oneclick.log` | 排查用 |
| sudo I/O 录像 | `/var/log/sudo-io/` | 审计用 |
| tailnet ACL | 控制台历史版本 | Revert |
