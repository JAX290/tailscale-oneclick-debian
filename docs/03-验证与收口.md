# 03 · 验证与收口

## 为什么分成两个阶段

`--lockdown` 会把 sshd 从 `0.0.0.0:22` 收到 `100.x:22`。如果 Tailscale SSH 或 ACL 还没配好，
**收口的一瞬间你就进不去了**（只剩云厂商 Web Console 可用）。

所以脚本故意拆成两个阶段：

```
阶段一  install.sh            → 装 Tailscale、建账号、装白名单。不动 sshd，随时可回退
阶段二  verify.sh + 手工验证   → 确认 Tailscale SSH 真的能进
阶段三  install.sh --lockdown → 才收口
```

## 阶段二：验证清单

### 1. 服务器上自检

```bash
sudo bash verify.sh
```

期望：`失败 0`。逐项说明：

| 检查项 | 失败说明 |
|---|---|
| tailscaled 运行中 | `systemctl status tailscaled` |
| 已登录 tailnet | `tailscale up` 没完成 |
| 100.x 地址 | 设备在 tailnet 里但没拿到 IP，看 `tailscale status` |
| RunSSH=true | 安装时用了 `--no-ssh`；重跑不带该参数 |
| 不在 sudo/wheel 组 | 账号建错了，`gpasswd -d opsagent sudo` |
| sudoers 权限 440 root:root | 被改动过，重跑 install.sh 会重新写 |
| 三个 ops-* 工具就位 | 没装或权限被改 |
| 监听 100.x:22 / 127.0.0.1:22 | 已收口，正常 |
| 监听 0.0.0.0:22 | **未收口**，跑 `--lockdown` |

### 2. 从你自己的电脑验证

```bash
tailscale status                    # 能看到 web1 且是 online
tailscale ssh opsagent@web1         # 应该能进
sudo ops-status                     # 应该能出完整状态
sudo -i                             # 应该被拒绝（不在 sudo 组 / 没有 ALL）
sudo ops-restart nginx.service      # 如果 nginx 不在白名单，应被拒绝
```

### 3. 验证 ACL 真的挡住了 root

```bash
tailscale ssh root@web1             # 应被 ACL 拒绝
```

如果这一步成功，说明 ACL 没改对（见 [02-首次配置-ACL.md](02-首次配置-ACL.md)）。**不要继续收口。**

### 4. 用第二台设备再验证一次

收口之后只剩 tailnet 能进，所以至少用**另一台设备**（手机也可以装 Tailscale）确认能登录。
一台设备验证等于没验证 —— 那台设备本身可能就是单点。

## 阶段三：收口

```bash
sudo bash install.sh --lockdown
```

它做的事：

1. 检查 Tailscale 已登录、拿到 `100.x`
2. 如果你当前连接来自公网 IP，会**警告并要求二次确认**
3. 备份现有 drop-in 到 `/etc/tailscale-oneclick/sshd-dropin.bak`
4. 写 `/etc/ssh/sshd_config.d/99-tailscale-oneclick.conf`：

```conf
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
ListenAddress 100.x.y.z
ListenAddress 127.0.0.1
```

5. `sshd -t` 校验；**失败自动删除并恢复备份**
6. `systemctl reload ssh`（已有连接不断）
7. 检查 `ss -ltn`，确认只剩 `100.x:22` 和 `127.0.0.1:22`

### 收口后会发生什么

- 公网 `22` 端口不再监听（扫描器看不到）
- root 不能登录 sshd
- 密码登录全部关闭
- 唯一入口：Tailscale 网络 + 你的 ACL

### 收口后的验证

```bash
sudo bash verify.sh          # 应显示监听 100.x:22 / 127.0.0.1:22，且 PermitRootLogin=no
```

再从公网试一次（应该是超时，不是拒绝 —— 因为根本没有监听）：

```bash
nc -vz <服务器公网IP> 22
```

## 出问题怎么办

| 症状 | 处理 |
|---|---|
| 收口后连不上 | 云厂商 Web Console / VNC 进去，执行 `bash install.sh --unlock` |
| sshd 起不来 | `sshd -t` 看报错；`rm /etc/ssh/sshd_config.d/99-tailscale-oneclick.conf && systemctl restart ssh` |
| Tailscale 自己挂了 | 同上，`--unlock` 恢复公网 22，再修 tailscale |
| ACL 改崩了 | 控制台 Access Controls 页面 Revert 上一个版本 |

**永远保留云厂商 Web Console 的登录入口**，这是最后的安全网。
